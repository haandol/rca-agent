# ADR 0006: 중단 조건 판단 — 신뢰도·비용·깊이 기반 탐색 종료

Date: 2026-04-21
Updated: 2026-09-15

## Status

Proposed

## Context

가설-트리 탐색이 무한히 계속되면 시간과 비용이 폭증하고 운영 통제가 불가능해진다. 적절한 시점에 탐색을 종료하고 보고서 생성으로 전환해야 한다.

## Decision Drivers

- 탐색 비용과 소요 시간에 상한이 있어야 운영이 통제 가능하다.
- 근본 원인이 확정되면 남은 예산을 소진하지 않고 즉시 보고서로 전환해야 한다.
- 근본 원인을 찾지 못한 채 예산이 소진되어도 SRE가 이어받을 결과물이 남아야 한다.
- 운영자가 진행 중인 분석을 중단시킬 수 있어야 하고, 중단이 완료된 세션의 결과를 훼손해서는 안 된다.

## Decision

**OR 조건 기반 다중 중단 조건**을 채택한다. 하나라도 충족되면 다음 탐색 작업을 시작하지 않는다. 활성 모델 응답의 수신과 명시적 취소는 아래 시간·소유권 계약을 따른다.

### 중단 조건

1. **신뢰도 임계치**: 채택 가설의 신뢰도가 **0.9 이상**
2. **Accepted Review Gate early exit**: 채택 가설이 있고 최대 신뢰도가 0.9 이상이면 **검증 루프 진입 전에** 종료한다. 0.8~0.9 구간에서 비확장 모드를 연속 2회 돌았음에도 0.9를 넘지 못하면 역시 종료한다([ADR 0002](0002-hypothesis-tree-lifecycle.md)).
3. **엔진별 시간 예산**: Strands SDK 경로는 전체 **3600초(60분)**를 신규 작업·재시도·다음 단계의 시작 예산으로 사용하며, 이미 데이터를 수신 중인 모델 응답을 총 경과 시간으로 끊지 않는다. Headless Codex 분석은 기존 **3600초(60분)의 강제 프로세스 종료 기한**을 그대로 유지한다. Strands의 종전 20분 예산만 확대하며 Headless의 기한 의미는 바꾸지 않는다.

### 승인된 런타임 예산

| 대상 | 값 | 의미 |
|---|---|---|
| Strands 전체 분석 | 3600초(60분) | 다음 분석 작업의 시작을 판단하는 전체 예산 |
| Headless Codex 전체 분석 | 3600초(60분), 기존 값 유지 | 기존 강제 프로세스 종료 기한; 활성 응답 예외를 적용하지 않음 |
| Strands 스코핑 단계 | 900초 | 단계 안에서 새 작업을 시작할 수 있는 예산 |
| Strands 가설 생성 단계 | 900초 | 새 모델 호출·후속 작업의 시작 예산 |
| Strands 기본 언어모델(LLM) 단계 | 각각 900초 | 우선순위·검증·분기·보고서·런북 생성 등의 시작 예산 |
| Strands 증거 수집 배치 | 1800초 | 배치 안의 가설별 신규 수집·재시도 시작 예산; 가설마다 1800초를 새로 부여하지 않음 |
| Strands SDK의 Bedrock 모델 응답 읽기 | 300초 | 첫 소켓 데이터까지, 이후에는 다음 소켓 데이터까지의 유휴 대기 한도 |
| 일반 AWS 응답 읽기 | 60초 | 모델 응답을 제외한 AWS 읽기 대기 한도 |

아래 스트리밍·활성 응답 보호·시작 예산 의미는 **Strands SDK 경로에만 적용한다.**
Headless 분석의 60분 강제 프로세스 기한과 승인 실행의 3600초 강제 종료 제어는 유지한다.
Headless 경로에 새로운 응답별 SDK 시간 한도를 도입하지 않는다.

Strands SDK 모델 응답은 스트리밍으로 수신한다. **이 응답 전체에 대한 총시간 제한은 없다.**
300초는 응답 시작부터 완료까지의 시간이 아니라 데이터가 오지 않는 연속 유휴 시간이다.
데이터를 계속 수신하는 응답은 900초 단계 예산이나 3600초 전체 예산을 넘겨도 그 이유만으로
취소하거나 실패로 처리하지 않는다. 배치·단계·전체 예산의 시작점을 재시도마다 초기화하지 않는다.

예산이 소진되면 새로운 모델 호출·도구 작업·재시도·다음 조사 단계의 시작을 거부한다.
현재 응답이 정상 종료하면 소유권을 확인한 뒤 받은 결과의 검증·보존과 기존 종료 처리를
수행한다. 예산을 넘겨 받은 정상 응답을 시간 초과의 늦은 결과로 오인해 버리지 않는다.
명시적 취소, 소유권 상실, 유휴 읽기 한도 초과 및 실제 전송 오류는 별도 중단 사유다.
취소·소유권 상실에는 응답 수신 중단을 요청하고 늦은 쓰기를 차단하며, 종료가 확인되지
않은 외부 요청과 새 시도를 중복 시작하지 않는다.

승인 실행의 전체 **3600초 강제 종료 기한**은 유지하며, 실행 도구와 배포·지표 대기 한도는
[승인 실행](0017-playbook-execution-agent.md)이 소유한다. Strands SDK 활성 응답 보호는
Headless 분석·승인 실행의 전체 기한에 적용되지 않는다. Strands 출력 토큰 한도는
[모델 계약](0010-model-tier-architecture.md)을 따른다.

정상 수신 중인 응답을 보존하는 대신 실제 경과 시간과 비용은 전체 시작 예산을 넘을 수 있다.
이를 정해진 시간에 강제로 끊는 것으로 해결하지 않고, 다음 작업의 시작 제한과 기존
신뢰도·깊이·검증·재생성 한도를 유지한다. 알람의 오래됨 기준과 정당한 처리 중 큐 가시성
갱신은 [알람 수신](../infra/0001-alarm-ingestion-sns-sqs-fargate.md)을 따른다.

4. **최대 깊이**: 가설 분기는 depth **3**까지 허용한다. depth 3 가설은 더 분기하지
   않으며 depth 4 이상인 가설은 유효한 탐색 결과가 아니다.
5. **최대 반복**: 검증 루프는 **최대 3회**다. 세 번째 루프가 끝나면 종료하고 네 번째
   루프를 시작하지 않는다.
6. **외부 취소 및 terminal 상태 진입**: 운영자가 세션을 취소하거나 세션이 완료·실패·만료 등 최종 상태에 들어가면 다음 상태 전이 시점에 파이프라인이 즉시 종료된다.

비용(토큰) 예산 기반 종료는 종료 사유 어휘에 자리를 두었으나 적용하지 않는다. 사용량 추적이 SDK 경계 밖에 있어 신뢰할 수 있는 집계가 없고, 부정확한 집계로 탐색을 중단하면 시간 예산보다 예측 불가한 종료가 된다. 비용은 신규 작업의 시간 예산·깊이·루프 한도와 Beam 폭으로 통제한다. Strands SDK 활성 모델 응답의 실제 비용을 벽시계 상한으로 보장하지 않는다.

### 핵심 결정사항

1. **순수 로직 (LLM 미사용)**: 중단 조건 평가는 LLM을 호출하지 않는다. 두 분석
   엔진은 같은 입력 상태에 같은 종료 결과를 내는 서버 판정을 사용한다. 모델이
   종료 사유나 다음 단계를 출력해도 권위가 없다.

2. **정상 중단**: 신뢰도 0.9 이상의 채택 가설이 있으면 그 가설을 최적 가설로 보고서 생성에 전달한다.

3. **강제 중단**: 시간·깊이·반복 한도 초과 시 누적 판정 중 최고 신뢰도 가설을 최적 가설로 선택해 보고서 생성에 전달한다. 확정에 이르지 못했어도 가장 유력한 후보는 남긴다.

4. **전체 기각 시 재생성**: 모든 가설이 기각되면 종료하지 않고 가설을 재생성한다(최대 2회). 한도를 초과하면 "근본 원인 미확정" 상태로 보고서를 생성한다. 전체 기각은 탐색 실패가 아니라 방향 전환 신호이므로 종료 조건과 분리한다.

5. **OR 평가 순서**: Accepted Review Gate → 확정 → 시간 예산 → 최대 깊이 → 최대
   루프 순서로 평가하고 첫 번째 충족 조건에서 즉시 반환한다. 게이트를 검증 루프
   진입 전에 두며, 세 번째 검증 루프 종료 후 계속 판정이 나와도 보고서 생성으로
   전환한다.

6. **Cooperative Cancellation**: 취소는 단계 전이의 조건부 쓰기와 실행 중 취소
   확인으로 감지한다. 최종 상태 세션의 전이는 실패하고, 파이프라인은 실패 기록으로
   terminal 결과를 덮지 않는다. 두 엔진 모두 같은 단계 상태를 기록하므로 취소 뒤
   늦은 산출물과 다음 단계 전이는 현재 claim에서 거부된다.

### Requirement contract

- **0.9 이상 채택 즉시 종료**: 다음 검증 루프나 분기가 시작되지 않고 같은 가설이 확정 원인으로 전달된다.
- **비확장 grace 2회**: 0.8 이상 0.9 미만 채택 가설이 연속 두 비확장 루프 뒤에도 임계를 넘지 못하면 해당 가설로 종료한다.
- **검증 루프 최대 3회**: validation 1·2·3은 가능하지만 validation 4는 생성·저장·완료가 거부된다.
- **분기 depth 최대 3**: depth 3 노드는 자식을 만들지 않고 depth 4 결과는 거부된다.
- **재생성 최대 2회**: 세 번째 재생성 요청은 수행되지 않고 미확정 보고서로 전환한다.
- **Strands SDK 활성 응답 보호**: 스트리밍 중 소켓 데이터가 계속 도착하면 단계·전체 예산 경과만으로 응답을 끊지 않고, 예산 소진 후 새 작업은 시작하지 않는다.
- **유휴 읽기 구분**: Strands SDK의 Bedrock 읽기는 첫/다음 소켓 데이터까지 300초, 일반 AWS 읽기는 60초이며 모델 응답 전체의 총시간 한도로 해석하지 않는다.
- **미확정 결과 보존**: 시간·깊이·루프 한도로 종료해도 가장 유력한 후보와 종료 사유가 보고서에 남는다.

7. **미검증 가설 CLOSED 처리**: 루프 종료 후 보고서 생성 전에 미검증·추가조사 상태로 남은 가설을 CLOSED로 정리하고 종료 사유를 함께 기록한다. 기각은 증거로 반증된 가설에만 쓰고, 예산 소진으로 검증되지 못한 가설과 구별한다 — 둘을 섞으면 보고서 독자가 "반증됨"과 "확인 못 함"을 구별할 수 없다. 최적 가설은 이 정리에서 제외한다.

### 운영자 취소

대시보드에서 세션을 취소하면 세션 상태가 취소로 바뀌고 해당 RCA의 미검증·추가조사 가설이 CLOSED로 정리된다. 이미 최종 상태(완료·실패·만료·취소)인 세션은 취소할 수 없고 그 요청은 충돌로 거부된다 — 완료된 RCA의 결과를 늦은 취소가 훼손해서는 안 된다. 명시적 취소는 활성 모델 응답에도 중단을 요청하고 현재 claim의 늦은 결과 확정을 차단한다. 원격 요청 종료가 확인되기 전에는 같은 작업을 다시 시작하지 않는다.

정리된 각 가설에는 종료 사유가 함께 기록되어, 보고서 독자가 그 가설이 왜 검증되지 않았는지(시간 예산 소진, 최대 깊이 초과, 운영자 중단 등) 구별할 수 있다.

## Consequences

### Positive

- 다중 중단 조건으로 운영 통제 확보 — 신규 작업의 시작과 탐색 범위 통제
- 정상/강제 중단 분리로 최적 시나리오와 최악 시나리오 모두 처리
- 미확정 시에도 보고서가 생성되어 SRE가 수동으로 이어서 분석 가능
- 두 엔진이 모델 구현과 시간 예산이 달라도 같은 탐색 상한과 종료 의미를 가짐

### Negative

- 시간 예산이 복잡한 장애에 부족할 수 있음
- 강제 중단 시 근본 원인이 확정되지 않은 보고서가 생성될 수 있음
- 취소를 요청해도 원격 요청 종료가 즉시 확인된다고 단정할 수 없으므로, 늦은 결과 차단과 종료 확인을 함께 유지해야 한다.
- 모델 응답 수신 시간이 엔진마다 다르므로 평가 경로에서 같은 장애에 대한 종료 시각은 갈릴 수 있다.
  다만 루프·깊이·확정 의미는 같으므로 차이는 실행 시간과 증거 품질에 한정된다
- 단일 장시간 실행 엔진의 예산을 늘리면 그 회차가 점유하는 시간도 늘어난다. 건너뛰기 기준을 함께 올려 알람 폐기를 막지만, 그만큼 **오래된 알람으로 분석을 시작**할 수 있다 — 장애가 이미 해소된 뒤 시작한 분석은 복구 흔적을 원인으로 오독할 여지가 있다

### Risks

- 중단 조건 임계치가 너무 느슨하면 비용 폭증, 너무 엄격하면 정확도 저하. 운영 데이터로 조정한다.
- 토큰 예산 종료가 없으므로 사고 토큰이 많이 소모되는 세션의 실제 비용은 신규 작업의 시간 예산·루프 한도로 간접 제어된다. Strands SDK 활성 응답에는 총시간 상한이 없지만 Headless 분석·승인 실행의 기존 강제 기한은 유지한다.

## 대안 검토

| 대안 | 장점 | 단점 및 미채택 이유 |
|------|------|---------------------|
| 단일 조건(확정 시에만 종료) | 규칙이 단순하고 품질 저하가 없다. | 확정에 이르지 못하는 장애에서 무한히 탐색해 비용과 시간 통제가 불가능하다. |
| Strands SDK 전체 예산 도달 시 활성 응답도 강제 종료 | 실제 경과 시간을 제한할 수 있다. | 계속 수신 중인 유효한 응답까지 버리므로 채택하지 않는다. 전체 예산은 다음 작업의 시작을 제한한다. |
| 장시간 엔진도 단계별 산출물 저장 후 조기 종료 | 예산 초과에도 부분 결과가 남아 짧은 예산을 쓸 수 있다. | 그 엔진은 하나의 실행 안에서 컨텍스트를 유지하는 것이 채택 이유이고([ADR 0011](0011-cc-headless-prompt-driven-rca.md)), 단계마다 결과를 확정하면 그 이점이 사라진다. 산출물 저장 시점을 늘리는 것과 예산을 늘리는 것 중 후자가 결정을 바꾸지 않는다. |
| LLM이 종료 시점을 판단 | 맥락을 반영한 유연한 종료가 가능하다. | 같은 상태에서 다른 결정이 나와 예산 상한이 성립하지 않고, 종료 판단 자체가 추가 호출 비용이 된다. |
| OR 조건 기반 다중 중단 조건 | 정상 종료와 강제 종료를 모두 결정론적으로 처리하고 신규 작업의 예산 판정이 보장된다. | 임계치가 여러 개라 튜닝 지점이 늘고, 강제 종료 시 미확정 보고서가 생성된다. |
