# ADR 0008: 플레이북 생성 — 유사 장애 대응 절차의 축적과 유사도 인덱싱

Date: 2026-04-21

## Status

Accepted (2026-04-21)

## Context

동일 유형의 장애가 재발할 때 과거 경험을 즉시 활용하려면, RCA 결과를 재사용 가능한 플레이북으로 자동 변환하고 벡터 검색이 가능하도록 인덱싱해야 한다. 플레이북은 장애 대응 절차(임시 조치, 영구 조치, 예방 조치, 에스컬레이션 기준 등)를 기록하며, 소비처는 두 곳이다. 신규 RCA 발생 시 동일 유형의 기존 플레이북을 보강하는 "Search-First" 병합, 그리고 복구 절차의 사람용 참조다. 초기 스코핑 단계의 유사도 검색은 플레이북이 아니라 RCA 보고서 인덱스를 사용한다([ADR 0001](0001-initial-scoping-and-report-similarity.md)) — 플레이북은 "어떻게 대응하는가" 중심이라 가설 생성에 필요한 "증상 → 근본 원인" 경로가 빈약하다.

## Decision Drivers

- 같은 유형의 장애가 반복될 때 플레이북이 중복 축적되지 않고 하나가 점진적으로 보강되어야 한다.
- 플레이북 검색은 표현이 달라도 같은 장애 유형을 찾아야 한다. 유사도 매칭이 수치 차이에 걸려 실패하면 병합이 일어나지 않는다.
- 기존 플레이북을 보강할 때 과거 내용이 사라져서는 안 된다. 축적이 되돌려지면 플레이북의 가치 자체가 없다.
- 플레이북 생성 실패가 RCA 파이프라인을 중단시켜서는 안 된다.
- 플레이북 절차가 자동 복구의 실행 근거가 되어서는 안 된다([ADR 0012](0012-automated-remediation.md)).

## Decision

**LLM 기반 플레이북 자동 생성 + 벡터 인덱싱** 전략을 채택한다.

### 플레이북 구조

- 장애 유형 분류 (예: DB 커넥션 누수, CPU 폭증, 메모리 릭 등)
- 증상 패턴 (어떤 알람/메트릭이 이 유형의 장애를 시사하는지)
- 심각도 판단 기준 (이 패턴 발생 시 critical/high/medium/low 구분 조건)
- 확인 절차 (단계별 검증 방법 — 이번 RCA에서 검증한 경로 기반)
- 임시 조치 절차 (예: 롤백, 리소스 증설)
- 영구 조치 가이드 (코드 수정 방향, 설정 변경)
- 에스컬레이션 기준 (언제, 누구에게 에스컬레이션할지)
- 예방 조치 (모니터링 추가, 알람 임계치 조정)
- 관련 메트릭 (이 장애 유형과 관련된 핵심 메트릭 및 대시보드)

### 핵심 결정사항

1. **검색 우선(Search-First) 전략**: 플레이북 생성 전에 벡터 인덱스에서 유사 플레이북을 검색한다. 유사도 **0.86 이상**인 기존 플레이북이 있으면 LLM이 새 RCA 결과와 비교해 보강할 내용이 있는지 판단한다. 보강이 필요하면 기존 플레이북 식별자를 유지한 채 내용을 갱신하고, 불필요하면 새 플레이북 생성도 건너뛴다. 임계치를 0.86으로 높게 두는 이유는, 다른 유형의 장애를 같은 플레이북으로 병합하면 절차가 뒤섞여 어느 쪽에도 쓸 수 없어지기 때문이다.

   **보강 판단 전에 기존 플레이북의 상세 절차를 반드시 로드한다.** 벡터 인덱스는 경량 메타데이터만 보유하므로(결정사항 4) 인덱스에 담긴 RCA 식별자로 상태 저장소를 한 번 더 조회한다. 상세 로드에 실패하면(레코드 만료·조회 실패) 그 후보는 보강 대상에서 **제외**하고 다음 후보로 넘어간다 — 기존 절차를 보지 못한 상태의 "보강"은 같은 식별자로 과거 내용을 덮어써 축적을 되돌리므로, 병합을 포기하고 신규 생성으로 떨어지는 편이 안전하다.

2. **벡터 임베딩 템플릿 공유**: 장애 유형·증상 패턴·메트릭으로 구성된 구조화 템플릿으로 임베딩 텍스트를 만들고, 각 필드를 상한 길이로 truncate한다. 저장과 검색에 각 용도에 맞는 입력 유형을 적용한다. **RCA 보고서 인덱스와 같은 템플릿을 사용**해 두 인덱스의 임베딩 공간 일관성을 유지한다([ADR 0001](0001-initial-scoping-and-report-similarity.md)).

3. **병합 규칙을 코드로 보장**: 보강 여부와 갱신된 플레이북 내용을 구조화 출력으로 받되, LLM이 특정 필드를 비워 반환하면 기존 값을 유지한다. "추가·보강만 하고 삭제하지 않는다"는 규칙을 프롬프트 지시가 아니라 코드에 둔다 — 프롬프트 지시만으로는 모델이 필드를 누락할 때 축적이 조용히 사라진다.

4. **벡터 인덱스는 경량 메타데이터만 보유**: 인덱스 메타데이터에는 크기 제한이 있어 검색·판별에 필요한 최소 필드와 RCA 식별자만 담고, 확인·조치 절차 같은 상세는 상태 저장소에서 조회한다. 상세를 인덱스에 중복 저장하면 갱신 시 두 저장소가 어긋난다([ADR infra/0002](../infra/0002-evidence-storage.md)).

5. **태깅**: LLM이 생성한 태그를 플레이북에 포함해 유형별 분류에 활용한다.

6. **타임아웃 및 fallback**: 각 LLM 호출에 타임아웃을 적용하고, 실패 시 최소 정보만 담은 플레이북을 생성한다.

7. **비차단(non-blocking) 실행**: 플레이북 생성은 파이프라인을 중단시키지 않는다. 실패하면 실패를 기록하고 알림·세션 완료로 계속 진행한다. 양쪽 엔진에 동일하게 적용한다 — 플레이북은 미래를 위한 자산이고 이번 RCA의 결과물은 보고서이므로, 자산 생성 실패가 결과 전달을 막아서는 안 된다.

8. **모델 티어**: **Planning 티어**를 사용한다. 장애 패턴 추출, 절차 작성, 기존 플레이북 업데이트 판단에 추론이 필요하다([ADR agent/0010](0010-model-tier-architecture.md)).

### 자동 복구와의 경계

플레이북은 자동 복구의 실행 근거가 아니다. 자동 복구는 검증 단계가 증거로 확정한
원인 유형과 서버 측 허용 목록만으로 대상을 결정하며([ADR 0012](0012-automated-remediation.md)),
플레이북의 조치 절차를 읽어 실행하지 않는다. 플레이북 절차를 복구 실행 경로에 넣으면
LLM이 생성한 자유 텍스트가 쓰기 액션의 권위가 되어 fail-closed 경계가 무너진다.
플레이북은 사람이 참조하는 대응 지식과 같은 유형 장애의 점진적 보강에만 쓰인다.

## 대안 검토

| 대안 | 장점 | 단점 및 미채택 이유 |
|------|------|---------------------|
| RCA마다 새 플레이북 생성 (검색 없음) | 구현이 가장 단순하고 LLM 호출이 1회다. | 같은 유형 장애가 반복될 때마다 유사 플레이북이 쌓여 어느 것이 최신인지 알 수 없고, 축적이 보강이 아니라 중복이 된다. |
| 장애 유형 문자열로 정확 일치 검색 후 병합 | 결정적이고 조회가 빠르다. | 유형 표현이 조금만 달라도 같은 장애가 별개로 취급된다. 유형 어휘를 사전 고정하면 예상하지 못한 장애 패턴을 담을 수 없다. |
| 유사도 검색 없이 사람이 병합 결정 | 잘못된 병합이 없다. | 자동 축적의 이점이 사라지고 플레이북이 사람 개입 없이는 갱신되지 않는다. |
| 유사도 검색 후 LLM 병합 판단 (Search-First) | 표현이 달라도 같은 유형을 찾아 하나를 점진 보강한다. | 임계치 튜닝이 필요하고, 유사도 해석이 틀리면 무관한 플레이북을 병합하거나 병합이 전혀 일어나지 않는다. |

## Consequences

### Positive

- 검색 우선 전략으로 중복 플레이북 축적 방지 — 동일 유형 장애의 플레이북이 점진적으로 보강됨
- 과거 RCA 경험이 플레이북으로 체계적으로 축적되어 조직 지식 자산화
- 유사도 인덱싱으로 동일 유형 장애의 플레이북을 찾아 보강할 수 있다
- 재발 장애 대응 시 사람이 참조할 검증된 절차가 남아 MTTR이 추가로 단축된다

### Negative

- 플레이북 품질이 RCA 결과의 정확도에 의존 — 오판된 RCA에서 잘못된 플레이북 생성 가능
- 임베딩 저장이 실패하면 검색이 불가하다 (플레이북 본문은 보존됨)
- 보강 판단을 위한 LLM 호출과 상세 로드 조회가 후보당 추가로 발생한다
- 플레이북 상세의 수명이 상태 저장소 보존 주기에 묶인다. 보존 기간이 지난 플레이북은 검색되어도 상세를 로드할 수 없어 병합 대상에서 제외되고, 같은 장애 유형의 플레이북이 새 식별자로 다시 생성된다

### Risks

- 근본 원인 미확정 RCA에서 생성된 플레이북이 향후 유사 장애 시 오도할 수 있다. "추정 원인 기반" 플레이북으로 명시하고 검증 부족 항목을 표기하여 완화한다.
- 유사도 임계치를 거리로 오해석하면([ADR 0001](0001-initial-scoping-and-report-similarity.md)) 보강 경로의 통과 조건이 반전되어, 무관한 플레이북을 병합하거나 반대로 병합이 전혀 일어나지 않는다. 어느 쪽이든 조용히 실패하므로 거리→유사도 변환을 인덱스 어댑터로 단일화하고 계약 테스트로 고정한다.
