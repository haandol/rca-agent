# ADR 0004: Vital Sensor 서비스와 내구 이벤트 저장 — RCA 검증 환경

Date: 2026-04-22
Updated: 2026-09-18

## Status

Proposed

## Context

RCA 에이전트의 정확도는 실제 클라우드 환경에서 장애 시나리오를 재현해야 검증할 수
있다. Vital Sensor 앱은 심박수 중심의 센서 측정을 저장하는 서비스다. 이벤트 형식의
변경을 물리 데이터베이스 컬럼 변경으로 잘못 옮긴 장애를 재현한다. 저장 실패 중에도
이미 받은 이벤트를 보존해야 롤백이 새 요청뿐 아니라 미완료 데이터까지 회복하는지
확인할 수 있다.

## Decision Drivers

- 센서 데이터가 영속 저장소에 쌓이고 정상 상태 메트릭이 축적되어야 RCA 에이전트가 이상을 판정할 수 있다. baseline이 없으면 모든 값이 정상으로도 이상으로도 보인다.
- 실제 저장 SQL 한 곳의 컬럼 불일치로 저장만 실패하고 조회·기동·연결 정리는 유지되어야 원인과 복구 효과를 구별할 수 있다.
- 데모 서비스는 외부에서 접근할 수 없어야 한다. 의도적으로 장애를 주입하는 환경이므로 노출되면 안 된다.
- 데모 목적에 비해 상시 비용이 과하지 않아야 한다.
- 주입한 장애는 플레이북 실행이 되돌릴 수 있는 상태여야 한다. 복구 대상이 없으면 실행 경로를 검증할 수 없다([ADR agent/0017](../agent/0017-playbook-execution-agent.md)).

## Decision

관계형 데이터베이스와 Vital Sensor 서비스를 독립 스택으로 배포한다. 기존 PostgreSQL에
미완료 이벤트를 보존하고, 서비스 전체의 단일 생성자가 초당 한 건의 새 이벤트를 만든다.
정상·결함 버전은 같은 입력과 보존 경로를 사용하며 실제 측정 INSERT의 컬럼 참조만 다르다.

### Requirement contract

- 데이터베이스와 서비스는 사설 네트워크에서 동작하고 자격 증명은 비밀 참조로 주입한다. 배포 구성과 이미지에 자격 증명을 포함하지 않는다.
- 서비스 전체에서 새 센서 이벤트를 초당 1건 생성한다. 태스크가 여러 개여도 생성자는 하나이며, 신규 생성은 저장 재시도의 완료 속도에 묶이지 않는다.
- 이벤트는 고유 ID·센서 식별자·측정 종류·값·단위·원래 측정 시각·스키마 버전을 가진다. 같은 ID와 다른 내용의 입력은 충돌로 거부하고 기존 내용을 바꾸지 않는다.
- 이벤트 v1의 측정 시각은 `timestamp`, v2는 `sampled_at`이다. 정상 버전은 둘 다 물리 테이블의 `timestamp`에 저장하며, 결함 버전도 같은 v2 이벤트를 받는다.
- 생성 직후 보존된 미완료 이벤트는 태스크 교체·롤백 후에도 같은 ID·측정 시각·값으로 재시도한다. 메모리에만 둔 값을 수신·보존 성공으로 표시하지 않는다.
- 측정 저장과 미완료 이벤트 완료 처리를 한 트랜잭션으로 확정한다. 응답 유실·동시 재시도에도 이벤트 하나의 측정 행은 한 번만 저장되며, 완료된 ID의 다른 내용도 충돌로 거부한다.
- 완료된 미완료 레코드는 삭제하고 측정 행은 기존 보존 정책을 유지한다. 중복 판정에 필요한 식별 정보는 해당 측정 행과 연결해 보존한다.
- 미완료 이벤트는 서비스 전체 최대 86,400건이다. 한도에 도달하면 기존 이벤트를 버리지 않고 신규 생성을 중단하며 생성하지 못한 건수를 별도 계수한다. 시간 경과만으로 미완료 이벤트를 삭제하지 않는다.
- 재시도는 지수적 간격과 무작위 지연을 사용하고 동시 실행 수·최대 간격을 제한한다. 실패한 연결을 반납한 뒤 다음 시도를 예약하며 신규 생성과 재시도를 분리한다.
- 모든 앱 태스크나 PostgreSQL이 중단된 구간은 생성·수신했다고 주장하지 않는다. 재기동 후 그 구간을 소급 생성하거나 몰아서 보내지 않는다.
- 정상 이미지가 기본이며, 같은 소스 스냅샷에서 저장 SQL의 컬럼 참조만 다른 불변 정상·결함 이미지를 만든다. 활성 시나리오와 주입 진입점은 이 컬럼 불일치 하나만 제공한다.
- 요청 상태, SQL 횟수·시간, 연결 수명과 유효 풀 설정을 관측하되 SQL 매개변수와 자격 증명을 기록하지 않는다. 지표 방출은 요청 완료에 의존하지 않는다.
- 서비스의 종료·실패·종료 신호에서 소유한 작업과 연결을 정리한다. 저장 실패 뒤 트랜잭션을 정상 정리하며 부분 저장과 연결 누수를 남기지 않는다.
- 배포된 이미지와 소스 리비전을 식별할 수 있어야 하며 정상·결함·복원은 같은 부하 조건으로 검증한다.
- 신규 이벤트·실제 SQL 시도·실패·재시도·미완료 건수·고유 저장 완료를 구분한다. 중복 응답을 새 측정 저장으로 계수하지 않는다.

### 데이터베이스

- **네트워크 격리**: 사설 서브넷에 두고 VPC 내부에서만 데이터베이스 포트 접근을 허용한다.
- **자격 증명**: 비밀 관리 서비스가 생성·보관하고 서비스는 참조로만 주입받는다. 자격 증명이 배포 구성이나 이미지에 들어가면 안 된다.
- **비용 최적화**: 데모 규모에 맞는 최소 인스턴스 등급과 스토리지를 사용한다. 자동 스케일링이 필요한 규모가 아니다.
- **개발 환경 수준 보호**: 삭제 보호를 두지 않는다. 데모 환경은 재생성이 정상 운영이며, 삭제 보호는 반복 검증을 방해한다.
- **이벤트의 관계와 접근**: 고유 이벤트 ID가 미완료 입력과 최종 측정을 연결한다. 새 입력 수용 시 동일 ID의 내용과 서비스 전체 수용 여유를 함께 검사한다. 처리기는 재시도 시각이 된 미완료 입력을 읽고, 측정 저장과 완료 처리를 함께 확정한다. 충돌·동시 처리·커밋 응답 유실에도 기존 입력과 단일 저장 효과가 유지된다.
- **추가 스키마와 호환성**: 미완료 입력·중복 판정·생성자 조정을 위한 저장 구조는 기존 데이터를 지우지 않고 추가한다. 정상·결함·롤백 버전 모두 같은 이벤트와 저장 구조를 이해해야 한다. 측정 테이블의 `timestamp`를 결함에 맞춰 `sampled_at`으로 바꾸지 않는다.

### Vital Sensor 서비스

- **DB 연결 구성**: 접속 대상은 환경 설정으로, 자격 증명은 비밀 참조로 주입한다.
- **배경 이벤트 생성**: 서비스 전체의 단일 생성자가 심박수 중심의 측정을 초당 한 건 만든다.
  미완료 이벤트 수용과 별도의 처리·재시도를 통해 저장 오류가 신규 생성 주기를 막지 않는다.
  포화 시에는 보존된 입력을 유지하며 생성 중단을 관측한다. 기존 조회 기능과 일부 이상치
  데이터는 유지하고 정상·결함·복원 구간에 같은 생성 조건을 적용한다.
- **실제 저장 컬럼 불일치**: PostgreSQL이 실행하는 `sensor_readings`의 INSERT
  한 곳에서 정상 `timestamp` 참조를 존재하지 않는 `sampled_at`으로 바꾼다.
  실제 드라이버 오류 SQLSTATE `42703`이 발생해야 한다. ORM(객체와 테이블을 연결하는
  계층) 모델·테이블 정의·기동 초기화·조회·트랜잭션 정리는 정상 경로를 유지한다.
  DB 호출 전 인자 오류, 기동 실패, 자동 스키마 변경은 이 결함의 성공이 아니다.
- **이미지와 스키마 전제**: 같은 소스 스냅샷의 정상·결함 이미지 차이가 저장 SQL
  참조에 한정되는지 대조하고, 태스크 정의는 이미지 지문을 직접 참조한다. 새 리비전
  식별자를 사용한다. 주입 전 실제 컬럼 조회에서 `timestamp` 존재와 `sampled_at`
  부재를 확인하며 전제가 다르면 중단한다. 전제를 맞추려고 컬럼을 추가하거나 데이터를
  삭제하지 않는다. 기존 데이터·센서 조회·알림 조회·헬스 응답 본문을 보존한다.
- **안전한 실제 진단**: 실제 드라이버 오류의 허용된 필드에서 SQLSTATE·오류 종류·관계,
  요청 시각·식별자, 매개변수를 제외한 INSERT 식별자·지문을 추출한다. 컬럼명이
  별도 제공되지 않으면 실제 SQL 식별자와 실제 컬럼 목록을 대조하며 필드를 추정하지
  않는다. 실패한 트랜잭션 밖의 읽기 전용 경로에서 스키마와 관측 시각을 얻는다.
  SQL 매개변수·환자 값·자격 증명은 HTTP 오류, 배경 작업 로그, 트레이스와 저장 증거에
  노출하지 않는다. 민감 시험값의 비노출과 정상→실제 오류→정상 저장을 확인해야 한다.
  분석 워커에 DB 쓰기 권한을 추가하지 않는다.
- **보존과 복구 확인**: 새 입력 수용, 동일 입력 재전달, 다른 내용의 ID 충돌, 저장 실패,
  커밋 응답 유실과 태스크 교체를 구분해 확인한다. 롤백 뒤 장애 중 보존한 이벤트가
  원래 측정 내용으로 한 번씩 저장됐는지는 신규 요청 성공과 별도로 검증한다.
- **배포된 코드 상태 노출**: 배포된 리비전 식별자를 실행 환경에 명시해 에이전트가 어떤 코드가 실행 중인지 저장소와 대조할 수 있게 한다.
- **관측과 수명 관리**: 요청 시작·완료·실패·진행 중 작업, SQL 호출 수와 소요 시간,
  연결 획득·반환과 실제 유효 풀 설정을 관측한다. SQL 매개변수나 자격 증명은 기록하지
  않는다. 지표는 요청 완료와 독립적으로 주기 방출하며 서비스 종료 시 부하·관측 작업과
  소유한 연결을 정리한다.
- **트레이싱은 선택적 구성**: 트레이싱 수집기를 사이드카로 붙일 수 있게 두되 기본 활성화하지 않는다. RCA의 자동 증거 수집 경로가 트레이스를 사용하지 않기 때문이다([ADR tools/0003](../tools/0003-trace-analysis.md)).

### 스택 간 순환 참조 회피

데이터베이스 보안 그룹이 서비스 보안 그룹을 참조하고 서비스가 데이터베이스를
참조하면 스택 간 순환이 생긴다. 데이터베이스 인바운드를 VPC 대역 전체로 열어 보안
그룹 상호 참조를 제거한다. 이는 개발 환경에서만 허용되는 완화이며, 같은 VPC의 다른
서비스가 데이터베이스에 접근할 수 있다는 대가를 감수한다.

## 대안 검토

| 대안 | 장점 | 단점 및 미채택 이유 |
|------|------|---------------------|
| 서버리스 데이터베이스(자동 스케일링) | 부하에 따라 용량이 조절되고 유휴 비용이 낮다. | 데모 목적에 비해 비용이 과하고, 단일 저장 컬럼 오류의 검증에 자동 용량 조절이 필요하지 않다. |
| 컨테이너 내 데이터베이스 | 별도 스택이 없고 비용이 거의 없다. | 컨테이너 재기동마다 데이터와 메트릭 baseline이 사라져 이상 판정 기준이 축적되지 않고, 관리형 데이터베이스 메트릭이 없어 증거 경로가 성립하지 않는다. |
| 외부 부하 생성기로 트래픽 주입 | 부하 패턴을 정밀하게 제어할 수 있다. | 생성기가 데모의 추가 실패 지점이 되고 실행마다 baseline이 달라져 이상 판정 기준이 흔들린다. |
| 최소 등급 관리형 데이터베이스 + 앱 내장 배경 트래픽 | baseline이 자동 축적되고 관리형 메트릭이 증거로 쓰이며 비용이 최소다. | 상시 비용이 발생하고, 부하 패턴 제어가 앱 구성에 묶인다. |
| 메모리에만 미완료 이벤트 보관 | 저장 구조가 단순하다. | 태스크 교체와 롤백 때 미완료 이벤트가 사라진다. |
| 별도 외부 내구 큐 | 데이터베이스 장애 중에도 입력을 보존할 수 있다. | 이번 계약은 완전 중단 구간의 생성을 보장하지 않으며 새 큐·권한·보존 정책을 추가할 필요가 없다. |
| 기존 PostgreSQL의 미완료 입력과 원자적 측정 저장 | 외부 큐 없이 재시작 보존·포화 제어·단일 저장 효과를 함께 검증한다. | 데이터베이스 전체 중단 동안은 신규 수신을 보장하지 않으며 조정 상태와 재시도 부하를 관리해야 한다. |

## Consequences

### Positive

- RCA 에이전트가 실제 클라우드 환경의 메트릭·로그로 분석을 수행한다
- 배경 트래픽으로 정상 baseline이 자동 축적되어 장애 주입 시 이상 패턴이 명확히 드러난다
- 최소 등급 구성으로 상시 비용을 억제한다
- 실제 저장 SQL과 이미지 변경이 실행 정의에 남아 배포 기반 원인 추적이 가능하다
- 완료되지 않은 요청과 처리량 감소를 구별하고 같은 부하로 복원 효과를 검증할 수 있다

### Negative

- 데이터베이스 상시 실행 비용이 발생한다
- VPC 대역 전체 인바운드 허용은 같은 VPC 내 다른 서비스의 데이터베이스 접근을 차단하지 못한다 (개발 환경에서만 허용)
- 삭제 보호가 없어 실수로 스택을 파괴하면 축적된 baseline이 사라진다
- 정상·결함 이미지와 부하·계측 경로를 함께 유지해야 한다
- 미완료 입력이 86,400건에 도달하면 새 측정 생성이 멈춘다. 기존 이벤트의 보존을 우선하는 의도된 포화 동작이다.

### Risks

- 서비스 재배포 시 데이터베이스 연결 실패로 배포가 롤백될 수 있다. 데이터베이스가 완전히 가동된 뒤 서비스를 배포한다.
- 자격 증명이 자동 생성되므로 스택 재생성 시 값이 바뀐다. 재생성 후에는 참조하는 모든 서비스가 새 비밀을 읽어야 한다.
- 생성자 교체나 재시도 경합이 중복 생성·저장으로 이어질 수 있다. 서비스 전체 생성 소유권과 수용 한도, 이벤트 유일성을 데이터베이스의 원자적 경계에서 확인한다.
