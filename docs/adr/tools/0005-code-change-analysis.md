# ADR 0005: 코드 변경 분석 — 저장소 MCP 서버 기반 결함 후보 탐지

Date: 2026-04-22

## Status

Accepted (2026-04-22)

## Context

배포 이력에서 의심 배포가 식별된 후([ADR 0004](0004-deploy-history.md)), 그 배포의
코드 변경을 분석해 장애를 유발할 수 있는 결함 패턴을 탐지해야 한다. 배포 → 코드까지
내려가는 경로가 성립해야 RCA가 "어떤 배포가 문제였다"를 넘어 "무엇이 잘못되었다"에
도달한다.

## Decision Drivers

- 코드 조회 도구를 자체 유지보수하지 않아야 한다([ADR 0001](0001-metrics-collection.md)).
- 배포 식별자에서 코드 변경으로 이어지는 조회 경로가 있어야 한다.
- 코드 접근 권한이 없거나 실패해도 RCA가 진행되어야 한다. 코드 분석은 증거의 한
  종류이지 필수 조건이 아니다.
- 저장소 접근은 읽기로 제한되어야 한다. 분석 에이전트가 저장소를 변경할 수 있으면
  읽기 전용 원칙이 깨진다([ADR agent/0011](../agent/0011-cc-headless-prompt-driven-rca.md)).

## Decision

**GitHub 공식 MCP 서버**를 양쪽 엔진의 도구로 등록한다.

### 핵심 결정사항

1. **읽기 전용 접근으로 제한**: 저장소 도구는 읽기 범위만 노출한다. 분석 경로에
   쓰기 도구가 존재하면 프롬프트 제약만으로 변경을 막는 구조가 되어, RCA의 읽기 전용
   보장이 도구 경계가 아니라 지시에 의존하게 된다.

2. **배포 → 커밋 → diff 경로**: 변경 이력에서 식별된 배포 커밋의 diff를 조회하고,
   필요하면 전후 커밋과 PR 범위, diff 주변 파일 내용까지 확장한다. 조회 깊이는
   가설에 따라 달라지므로 고정하지 않는다.

3. **LLM 결함 패턴 판정**: 수집된 diff에서 장애 유발 가능 패턴을 판정한다. 탐지
   대상은 리소스 미반환(커넥션·파일·스레드), 예외 처리 누락, 설정값·타임아웃 변경,
   쿼리 변경이다. 정적 규칙이 아닌 LLM 판정을 쓰는 이유는, 같은 코드 패턴이 맥락에
   따라 결함일 수도 정상일 수도 있기 때문이다.

4. **크기 초과 시 분할 분석**: diff가 컨텍스트를 초과하면 변경된 파일을 우선순위
   순으로 분할 분석한다. 전체를 한 번에 넣지 못한다고 분석을 포기하지 않는다.

5. **접근 실패를 수집 불가로 기록**: 저장소 접근 권한이 없거나 조회가 실패하면
   "수집 불가"로 표시하고 다른 증거로 RCA를 진행한다.

## 대안 검토

| 대안 | 장점 | 단점 및 미채택 이유 |
|------|------|---------------------|
| 저장소를 컨테이너에 클론해 로컬에서 분석 | 네트워크 의존과 API 레이트 리밋이 없다. | 저장소 크기만큼 이미지·디스크가 커지고, 배포 시점 커밋을 얻으려면 전체 이력을 받아야 한다. 클론 상태를 최신으로 유지하는 책임이 새로 생긴다. |
| 정적 분석 도구로 결함 패턴 탐지 | 결정적이고 재현 가능하다. | 같은 코드 패턴이 맥락에 따라 결함일 수도 정상일 수도 있어 오탐이 많고, 이 장애의 증상과 연결하는 판단은 여전히 필요하다. |
| 저장소 MCP 서버 + LLM 판정 | 도구 유지보수가 없고 diff·PR·파일 내용을 모두 조회하며, 증상과 코드를 함께 보고 판정한다. | 접근 토큰 관리가 필요하고 API 레이트 리밋에 걸릴 수 있다. |

## Consequences

### Positive

- 코드 조회 도구를 자체 유지보수하지 않는다
- 배포 이력과 연계해 장애 원인을 코드 수준까지 특정할 수 있다
- LLM의 코드 이해로 수동 리뷰 없이 결함 후보를 탐지한다

### Negative

- 저장소 접근 토큰 발급과 권한 관리가 별도로 필요하다
- 프라이빗 저장소 접근에는 넓은 스코프가 필요해 자격 증명 관리에 주의가 필요하다
- API 레이트 리밋으로 대규모 분석이 제약될 수 있다

### Risks

- 저장소 접근 권한이 없으면 코드 증거를 얻을 수 없다. "수집 불가"로 표시하고 메트릭·
  로그·배포 이력만으로 RCA를 진행한다.
- 결함 후보 판정이 오탐이면 잘못된 가설이 높은 신뢰도를 얻을 수 있다. 코드 증거만으로
  확정하지 않고 증상과의 시간 상관을 함께 요구한다.
