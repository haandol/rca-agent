# ADR 0003: 트레이스 분석 — 분산 트레이스 기반 증거 수집

Date: 2026-04-21

## Status

Deprecated (2026-04-21)

## Context

서비스 간 호출 흐름에서 병목이나 실패 지점을 파악하려면 분산 트레이스 데이터가
유용하다. 계측된 서비스의 트레이스를 에이전트가 자동 조회하는 경로를 검토했다.

## Decision Drivers

- 증거 수집 도구는 자체 유지보수 없이 등록만으로 붙어야 한다([ADR 0001](0001-metrics-collection.md)).
- 트레이스는 필수 증거가 아니다. 계측되지 않은 서비스에는 데이터 자체가 없으므로,
  다른 증거만으로도 RCA가 성립해야 한다.
- 조회한 증거는 LLM이 판정에 쓸 수 있는 형태여야 한다. 사람이 UI에서 읽어야 의미가
  드러나는 데이터는 증거로 기능하지 않는다.

## Decision

**분산 트레이스 기반 증거 수집을 채택하지 않는다.** 메트릭, 로그, 배포 이력, 코드
변경 증거만으로 RCA를 진행한다.

관리형 MCP 서버가 제공되지 않아 도구 계층을 자체 구현해야 하고, 트레이스 API를
래핑해도 반환되는 세그먼트 그래프는 LLM이 판정 근거로 쓰기 어렵다. 트레이스의 가치는
시각적 탐색에 있는데 그 형태를 텍스트 증거로 옮기는 비용이 얻는 판정 능력보다 크다.

이 결정은 트레이스가 무용하다는 뜻이 아니다. 데모 환경에는 트레이싱 계측이 선택적
구성으로 남아 있고 사람이 직접 조회할 수 있다. RCA 에이전트의 **자동 증거 수집
경로**에 포함하지 않는다는 결정이다.

## 대안 검토

| 대안 | 장점 | 단점 및 미채택 이유 |
|------|------|---------------------|
| 트레이스 API를 커스텀 도구로 래핑 | 서비스 간 호출 흐름 증거를 확보한다. | 관리형 서버가 없어 도구 계층을 자체 유지해야 하고, 세그먼트 그래프를 LLM이 판정 근거로 쓰기 어려워 유지비 대비 판정 능력 향상이 작다. |
| 트레이스를 요약해 텍스트 증거로 변환 | LLM이 소비할 수 있는 형태가 된다. | 어떤 스팬을 남길지 판단하는 요약 로직 자체가 RCA 추론이며, 이를 도구에 고정하면 가설과 무관한 요약이 나온다. |
| 트레이스 증거를 자동 수집에서 제외 | MVP 범위를 좁혀 메트릭·로그·배포 이력·코드 변경 경로에 집중한다. | 분산 시스템 장애에서 서비스 간 호출 흐름 증거가 없어 정확도가 낮아질 수 있다. |

## Consequences

### Positive

- 자동 증거 수집 범위를 좁혀 관리형 MCP 서버로 커버되는 경로에 집중한다
- 자체 유지보수할 도구 계층이 늘지 않는다

### Negative

- 서비스 간 호출 흐름을 증거로 사용할 수 없다
- 계측되지 않은 서비스에서는 트레이스 데이터 자체가 없어 이 결정의 실질 손실이 작다

### Risks

- 트레이스 증거 없이 서비스 간 호출 흐름을 판정해야 하므로 다중 서비스 장애에서
  정확도가 낮아질 수 있다. 메트릭과 로그로 보완한다.
