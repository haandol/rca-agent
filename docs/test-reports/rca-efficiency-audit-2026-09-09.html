1. RCA가 59분 걸려도 Report에 다시 60분을 줍니다

Codex 러너는 RCA 전문 프로세스를 실행한 뒤 Report 전문 프로세스를 실행합니다. 각 호출은 새로 시작한 프로세스에 3,600초 제한을 적용합니다. 두 단계가 공유하는 마감 시각은 없습니다. 모의 프로세스로 두 호출 모두 timeout=3600을 받는 것을 확인했습니다.

따라서 RCA가 제한 직전에 성공하면 Report가 추가로 거의 한 시간을 사용할 수 있습니다. 합계가 약 120분에 접근할 수 있다는 것은 코드에서 계산한 상한이며, 120분 운영 실행을 관측했다는 뜻은 아닙니다. 공용 큐의 메시지 숨김 시간은 65분입니다. 이를 넘기면 다른 워커가 메시지를 받아 더 높은 수신 횟수로 소유권을 가져갈 수 있습니다. 이전 워커의 결과 쓰기는 차단되더라도 이미 소비한 분석 시간은 회수할 수 없습니다.

수정: 러너 진입 시 단조 시계로 마감 시각을 한 번 만들고 단계마다 남은 시간을 전달합니다. 남은 시간이 없으면 다음 프로세스를 시작하지 않습니다. 전체 예산 60분과 큐 숨김 시간 65분을 유지하는 버그 수정이며, 시간 상한을 늘리는 방식으로 해결할 필요는 없습니다. 보고서 시간을 별도로 보장하도록 예산을 나누는 정책은 추가 결정입니다.

2. 만료된 알람이 새 알람을 막는 기록을 만듭니다

Headless Codex는 첫 수신에서 오래된 알람을 OUTDATED, 즉 만료 상태로 저장합니다. 그 메시지가 재전달되면 만료 여부를 먼저 확인하지 않고 활성 장애 기록부터 확보합니다. 이때 새로 만들어진 장애 기록에는 복구 신호가 없습니다. 같은 알람의 새 이벤트가 들어와도 “기존 장애의 복구를 아직 보지 못했다”는 이유로 처리를 보류합니다.

실제 저장소 구현과 Moto라는 로컬 AWS 모의 환경을 연결했습니다. 3시간 전 알람의 첫 수신 → 같은 메시지의 두 번째 수신 → 현재 시각의 새 알람 순서에서, 두 번째 수신이 활성 장애 기록을 만들었고 새 알람의 분석 호출은 0회였습니다. Strands에는 오래된 재전달의 최종 상태를 먼저 확인하는 방어가 이미 있습니다.

같은 분기에는 원본 SQS 메시지 ID 전달도 빠져 있습니다. 만료 상태 저장 전에 장애가 나면 세션에 direct:…가 저장됩니다. 재전달의 실제 메시지 ID와 달라 소유권 회수가 거부됩니다. 이 조합도 로컬에서 재현했습니다. 복구 이벤트나 운영 정리 없이 새 알람까지 보류될 수 있으며, 메시지는 설정된 재수신 한도를 소진할 수 있습니다.

수정: 오래된 재전달은 최종 상태를 먼저 읽어 만료·취소 메시지를 소비하고, 완료된 경우 남은 후처리만 수행합니다. 첫 만료 분기에도 원본 메시지 ID를 전달합니다. 기존 재시도·소유권 계약을 복원하는 버그 수정입니다.

3. 같은 부모가 다시 선택되면 동일 자식을 추가할 수 있습니다

추가 조사가 필요한 부모는 다음 루프에서 다시 분기할 수 있습니다. 분기 결과는 부모와 기각된 설명에 대해서만 중복 검사하고, 이미 생성한 형제 가설은 검사하지 않습니다. 같은 부모와 증거로 같은 자식 셋을 두 번 반환하게 한 재현에서는 자식 6개가 서로 다른 ID로 저장됐지만 설명은 3개뿐이었습니다. 이들이 후속 조사 대상으로 선택되면 수집과 검증이 반복됩니다.

수정: 모델 호출 전에 부모의 기존 자식 수와 남은 한도를 확인하고 결과를 기존 형제와도 비교합니다. 부모별 자식 최대 3개라는 기존 계약을 지키는 버그 수정입니다. “증거가 변하지 않으면 어떤 재분기도 금지”하는 더 넓은 정책은 별도 검토가 필요합니다.
