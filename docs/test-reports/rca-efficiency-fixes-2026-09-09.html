최초 8개 수정의 검증 기록입니다. 이후 추가 코드 교정과 실모델 평가를 수행했습니다. 최신 결과는 실모델 평가 보고서를 확인하세요.

점검에서 제시한 8개 수정 항목을 구현했습니다. 초기 오프라인 검증 당시 승인된 평가 입력 지문과 프롬프트가 달라 기준선 승인 단계가 남았습니다. 이후 실모델 평가에서는 8건 중 5건이 통과하여 기준선은 갱신하지 않았습니다. 운영 배포는 하지 않았습니다.

이 문서는 수정 전 점검 보고서의 후속 결과입니다. 가설의 상태·신뢰도 기준·깊이·루프·재생성 상한과 실행 승인 경계는 유지했습니다. 현재 계약을 지키는 버그 수정과 모델 입력 구성 개선으로 처리했으며 ADR과 승인 기준선은 변경하지 않았습니다.

어떤 동작이 달라졌는가

항목수정 후 동작회귀 검증
1. Codex 시간 예산RCA와 Report가 하나의 60분 마감 시각을 공유합니다. 준비 시간도 차감하고, 남은 시간이 없으면 다음 프로세스를 시작하지 않습니다.가짜 시계로 남은 시간 전달·준비 중 소진·Report 중 시간 초과·취소를 검사합니다.
2. Codex 만료 재전달오래된 재전달의 최종 상태를 활성 장애 기록보다 먼저 확인합니다. 처음부터 원본 메시지 ID를 보존합니다.Moto의 실제 SQS 재수신과 DynamoDB 조건부 쓰기로 새 알람 처리·미완료 소유권 회수·이전 소유자의 늦은 쓰기 거부를 확인합니다.
3. Strands 중복 분기기존 자식과 이번 응답의 중복을 제거합니다. 부모별 누적 최대 3개를 적용하고, 한도가 찼으면 모델을 호출하지 않습니다.반복 분기·남은 한도·대소문자 중복·미조사 자식 보존·대안 없는 실패 종료를 검사합니다.
4. Strands 검증 대화호출 전후에 대화를 비웁니다. 모델 설정과 연결은 재사용하고, 각 호출에는 현재 가설의 명시적 증거만 전달합니다.실제 설치된 Agent와 가짜 모델로 여러 가설·회차·세션, 예외·타임아웃 신호 후 재사용, SDK 내부 재시도를 검사합니다.
5. Strands 재생성 피드백기각 가설 ID별 이유와 증거 요약·참조를 제한된 입력으로 전달합니다. 이전 검증 루프의 기록도 보존합니다.여러 검증 루프와 재생성을 거쳐도 기각 증거가 유지되는지, 입력 크기가 제한되는지 검사합니다. 설명이 같다는 이유만으로 새 가설을 거부하지 않습니다.
6. Codex 보고서 중복 출력보고서와 플레이북 저장 뒤에는 짧은 완료 응답만 반환합니다. 최종 결과는 저장된 산출물에서 읽습니다.짧은 응답으로도 운영·평가 경로가 동일한 산출물을 소비하는지 검사합니다.
7. Codex 역할별 입력공유 원본에서 RCA용·Report용 입력을 각각 조립합니다. Report에 필요한 분석·플레이북 형식과 안전 규칙은 유지합니다.역할별 포함·제외 규칙, 관측 참조, 운영·평가 입력 경로를 검사합니다.
8. Strands 수신 오류 대기수신 실패와 빈 큐를 구분합니다. 연속 실패 때 대기를 늘리고 성공하면 초기화합니다. 종료 신호는 대기를 즉시 해제합니다.오류 대기 증가·상한·성공 후 초기화·종료 중 재수신 방지를 검사합니다.

두 프로세스가 시간을 나눠 쓰는 방식

마감 시각은 시스템 시각 변경에 영향을 받지 않는 단조 시계로 한 번 계산합니다. Report는 처음부터 60분을 다시 받지 않고 RCA와 준비 작업이 사용한 시간을 제외한 나머지를 받습니다. 예를 들어 RCA와 준비에 3,500초를 썼다면 Report에는 최대 100초가 남습니다.

Strands의 기존 타임아웃은 신호를 발생시켜도 SDK가 동기 호출의 작업 스레드를 정리할 때까지 기다릴 수 있습니다. 별도 가짜 모델 관측에서 0.020초 제한과 0.5초 작업을 사용하자 약 0.509초 뒤 반환했습니다. 이번 대화 격리 수정은 예외 뒤 정리와 다음 호출의 독립성을 보장하는 범위이며, 이 기존 호출 경로의 즉시 중단을 새로 보장하지 않습니다.

실제 CLI·외부 모델의 종료 지연, 운영 비용, 정확도, 인프라 메모리 사용량은 이번 오프라인 검증의 입증 범위에 포함되지 않습니다. 추적 수집기 자원 제한과 태스크 크기 조정도 원래 보고서의 측정 후 검토 후보로 남겼습니다.
