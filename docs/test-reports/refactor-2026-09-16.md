# 전체 패키지 리팩토링 검증

2026-09-16. 브랜치: `feat/single-scenario-recovery`.

코드 정리와 로컬 검증을 완료했다. 푸시는 기존 실모델 평가 승인 게이트 때문에
보류했다. 현재 단일 컬럼 장애 시나리오에 대한 두 엔진 결과가 없고 기준선은
`pending`이다. 로컬 테스트 통과를 모델 평가 승인으로 바꾸지 않았다.

## 변경 범위

이전 작업의 구현은 `971f6e5`에 먼저 보존했다. 이번 동작 보존 리팩토링은
`ccce6dc`의 10개 파일이며, 102줄 추가·119줄 삭제다.

| 영역 | 정리한 코드 | 보존한 동작 |
|---|---|---|
| Strands 보고서 | 성공·fallback의 원인 메타데이터 5개 필드를 공통 함수로 이동 | 서버가 선택한 원인·확정·신뢰도, 기본값, deep copy, 로그·예외 순서 |
| 실행 워커 | 승인 메타데이터 직렬화 중복 제거, 회고 함수의 미사용 내부 인자 제거 | JSON→Decimal→DynamoDB 변환, 승인 명령, S3 증거 기록·참조, 회고 게시 순서 |
| 대시보드 | 플레이북 가공 함수 3개를 별도 모듈로 이동 | 기존 export, 과거 기록과 게시 데이터의 서로 다른 제외 필드, Unicode 80자 처리 |
| 센서 서비스 | 세 HTTP 컨트롤러의 동일 응답 변환 통합 | 8개 응답 필드와 순서, 검증, 서비스 호출, 저장 SQL·트랜잭션 |
| 인프라 | 코드·테스트 검토, 구현 변경 없음 | 리소스·권한·환경변수·타임아웃 |

동작 보존 범위를 벗어나는 파이프라인 재구성, 권한 공통화, 과거 호환 함수 삭제는
적용하지 않았다. 소스가 바뀌었다는 사실을 배포 이미지 변경으로 해석하지 않는다.

로컬 실행 저널·브라우저 기록·생성된 검증 디렉터리는 `.gitignore`에 추가했고
파일은 삭제하지 않았다. 계획 문서에서 참조하는 과거 시나리오 리뷰는 함께 보존했다.

## 검증 결과

| 검사 | 결과 |
|---|---|
| `pnpm build` | 통과: 빌드 대상 3개 |
| 포맷·린트 | 통과 |
| Agent 테스트 | 1,175 통과, 실모델 선택 실행 2개 건너뜀 |
| Headless 테스트 | 2,079 통과 |
| Healthcare 테스트 | 150 통과, 명시적 실제 PostgreSQL 설정이 필요한 1개 건너뜀 |
| Infra 테스트 | 9개 suite, 110개 통과 |
| 루트 계약 테스트 | 305개 통과 |
| `pnpm typecheck` | 통과: 대상 2개 |
| `git diff --check` | 통과 |
| `pnpm verify` | 실패: 마지막 `eval:offline`에서 모델 승인·결과 부재 |

패키지·루트 계약 테스트 합계는 3,819개 통과다. 대시보드 별도 검증 224개는
루트 계약 테스트에 포함되므로 중복 합산하지 않았다. 마지막 전체 검증은 변경된
센서 코드도 포함하며, 변경 없는 일부 대상은 Nx 캐시를 재사용했다.

첫 전체 검증에서는 이전 시나리오 목록을 가리키는 입력 지문 불일치 1건이 있었다.
기존 `pnpm eval:sync-inputs`로 이전 기준선 원본을 이력에 보존하고 현재 입력을
기록한 뒤 계약 테스트 305개가 모두 통과했다. `status: pending`,
`approvedAt: null`은 유지했다.

인프라 테스트는 격리 복사본의 검증 환경에서 exit 139가 발생했으나, 원래 작업공간의
기본 실행과 전체 검증에서는 각각 110개가 통과했다. Healthcare 복사본의
`/private/tmp` 경로가 민감 문자열 검사의 `private`에 걸린 2건도 원래 작업공간에서
재확인했다. 이 과정에서 테스트 조건이나 기대값을 완화하지 않았다.

## 소스 대조와 ADR

구현 담당자 외 검토자가 보고서·실행 워커 변경을 원본과 대조했다. 보고서의
24개 전후 비교는 생성시각을 제외한 직렬화 결과, 설정 필드, 예외, 로그 순서,
deep copy 격리가 같았다. 대시보드 함수 본문과 상수는 원본과 동일하며 새 모듈은
import가 없어 순환 의존성을 만들지 않는다. 기존 export만 자동 import 대상이다.

ADR 구조 검사는 오류 0개, 기존 권고 경고 13개였다. Agent ADR 요약 14개의
quick sync는 저장소 일치 13개, 미검증 1개였다. 미검증 항목은 실모델·반복 데모의
채택 요건이며 성공으로 처리하지 않았다. 변경 경로의 승인·저장 계약도 대조했고
ADR 본문·레지스트리·상태는 변경하지 않았다. 전체 ADR 본문의 완전 감사를 뜻하지 않는다.

## 푸시 차단 조건

마지막 `eval:offline`의 실패는 다음 세 가지다.

```text
model evaluation approval is pending
missing result: headless-codex/write-column-regression
missing result: strands/write-column-regression
```

`scripts/hooks/verify-before-push.sh`는 `pnpm verify`가 실패하면 모든 push를
차단하도록 정의되어 있다. 게이트를 건너뛰거나 기준선을 임의로 승인하지 않았다.
현재 승인되지 않은 모델 결과를 과거 fixture로 대체하지도 않았다.

기존 게이트를 유지하려면 현재 입력으로 두 엔진의 실모델 평가를 실행하고 결과를
검토해 승인해야 한다. `tests/README.md`에 명시된 이 경로는 모델 호출뿐 아니라
설정된 DynamoDB·S3에 평가 기록을 쓰므로 로컬 리팩토링 검사와 범위가 다르다.
이번 작업에서는 AWS 배포·장애 주입·실모델 호출·운영 데이터 변경을 수행하지 않았다.
실제 장애의 원인 확정·복구 성공률은 이 보고서의 검증 결과에 포함하지 않는다.
