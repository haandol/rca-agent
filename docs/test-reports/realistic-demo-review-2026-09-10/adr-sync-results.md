# 대상 ADR 동기화 결과

세 대상의 승인된 결정과 요구 계약은 유지했다. 파일·정적 구성·테스트와 독립 코드 검토를 대조했으며 새 아키텍처 결정이나 요구값 변경을 추가하지 않았다. 코드 발견사항은 해결됐지만 전체 증거 판정은 INCONCLUSIVE이고 세 Status는 Proposed를 유지한다.

## 대상과 의미
- infra/0004: 사설 서비스·DB, 비밀 참조, 유한 부하, 실제 결함 이미지, 비노출 관측과 자원 정리. Decision/Requirement contract/Drivers/Consequences 변경 없음.
- infra/0007: 네 실제 장애, 같은 입력의 원상복원, 소유권·실패 정리, 기존 5+10/12/20/30초/60초×2/150초 계약. 변경 없음. 누락됐던 150초 사후 관측 하한은 코드에서 강제했다.
- agent/0016: 원본 메타데이터 보존, 사고 이전·중 관측, 두 엔진 공통 판정·안전성·기준선 승인. 변경 없음. 누락 메타데이터를 런타임 기본값으로 채우던 표시 경계는 수정했다.

## 증거 경계
이 동기화는 저장소 코드·IaC·로컬 테스트·기록된 독립 검토만 사용했다. 동기화 목적으로 라이브 환경에 접근하지 않았다. 별도 승인 범위의 모델 검증과 자원 정리 결과는 상위 검증 보고서에 따로 기록했다.

실제 AWS 증상 알람·배포 E2E와 현재 모델 품질·새 기준선 승인은 완료되지 않았다. 이를 ADR 계약 삭제나 임계치 완화로 해소하지 않았다. 배포 존재를 ADR Status의 새로운 선행조건으로 추가하지 않았다.

## 구조·색인
공식 adr-structure-lint의 infra/agent 결과는 모두 ok=true, errors=[]다. 경로·Status·mapping의 일치, Related 링크와 색인 구조를 확인했다. 기존 legacy 규칙 문서·번호 간격·driver 수 경고는 이번 세 결정의 변경으로 취급하지 않았다. Category와 dependsOn은 변경하지 않았다. 이미 작성한 category decision-log의 현재 ADR 링크와 변경 요약을 유지한다.

단위 1771개, 공통 계약 136개와 후속 복원 경계 56개 Python 검사가 통과했다. 공통 기준선 검사는 기존 승인 digest와 달라 실패한다. 최종 실모델 8개 모두 전체 필수 게이트에 실패하여 기준선과 승인 fixture를 갱신하지 않았다.
