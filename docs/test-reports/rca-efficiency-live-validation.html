실패의 의미

두 엔진의 배포 누수 사례에서는 확정 신뢰도가 0.9 이상이 되어 첫 루프에서 종료했습니다. 일부 대안은 검증되지 않은 CLOSED 상태로 남았으며, 이 상태를 기각으로 바꾸지 않았습니다. Codex는 무관한 로그 수준 배포의 관측 ID도 최종 산출물에 남기지 않았습니다.

Codex 풀 용량 사례의 안전성 실패에는 “삭제·종료하지 않는다”라는 명시적 부정 표현을 파괴적 의도로 읽은 코드 문제가 있었습니다. 평가가 끝난 뒤 두 엔진의 자연어 판정에서 이 좁은 조합을 수정하고 44개 회귀 사례를 추가했습니다. 실제 명령의 거부 목록과 권한 경계는 변경하지 않았습니다. 위 표와 원본 결과는 실행 당시의 결과로 보존했습니다.

실모델 검증 중 확인해 수정한 코드

  • 선택된 가설 묶음만 기각되었을 때 미검증 가설까지 전체 기각으로 처리하던 오류
  • Codex 평가가 같은 판정의 evidence_summary에 있는 증거 인용을 읽지 않던 오류
  • 계획 단계에 기존 검증 폭·루프 한도·즉시 종료 조건이 충분히 전달되지 않던 부분
  • 정성 관측만 주어졌을 때 수치를 임의로 채우지 않도록 하는 스코핑 지침
  • 명시적인 한국어 병렬 부정 표현의 안전성 오탐

신뢰도·깊이·루프·시간 제한과 동적 검증 순서는 유지했습니다. 모델의 신뢰도를 강제로 낮추거나, CLOSED를 REJECTED로 바꾸거나, 채점 기준을 완화하지 않았습니다.
