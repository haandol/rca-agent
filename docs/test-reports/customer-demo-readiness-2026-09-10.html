풀 설정 회귀교체용 예비설정 변경으로 동시 요청을 감당하지 못하다가 정상 설정 롤백으로 회복하는 이야기입니다. 기본 동시성 1·5초 간격으로는 장애가 안 날 수 있습니다. 같은 부하와 timeout을 준비하고 풀 용량만 바꿉니다. 정상 태스크 정의를 미리 등록해 승인 실행은 기존 정의로 되돌리게 합니다. 배포 안정화 시간이 추가됩니다.

예외 세션 반환 누락기술 심화용양수 limit의 정상 트래픽만으로는 재현되지 않습니다. 현재는 음수 limit 오류 요청을 반복해야 하고, 누수 누적과 정상 이미지 재배포·기존 프로세스 정리가 필요합니다. 현장 설명과 트리거 조건이 늘어나므로 짧은 첫 데모에서는 제외합니다.

발표 시간을 줄이는 준비

  • 이미지 빌드·정상/장애 태스크 정의 등록·데이터 준비·정상 지표 축적·임계치 보정은 현장 시연 전에 마칩니다.
  • 같은 서비스·데이터·부하에서 한 원인만 바꿉니다. 실행 도중 임계치나 요청량을 조절해 알람을 억지로 맞추지 않습니다.

  • 실제 환경에서 전체 흐름을 반복 리허설하고, 선택한 발표 예산 안에 연속 완주하는지 확인합니다. 15분은 목표 예산이며 현재 검증된 완료 시간은 아닙니다.
  • 10~15분이 엄격한 상한이라면 실제 분석 실행 기록을 설명한 뒤 승인·복구를 라이브로 보여주는 구성을 검토합니다. 준비된 기록과 현재 라이브 단계는 화면과 말로 분명히 구분합니다. 처음부터 끝까지 완전 라이브여야 한다면 리허설 실측 뒤 시간을 확정합니다.

정비 잠금의 추가 통합 문제

AWS StopTask 공식 문서는 태스크 종료 시 관련 태그가 삭제된다고 설명합니다. 현재 Demo.owned_tasks는 STOPPED 태스크에도 태그 일치를 요구합니다. 문서에 맞춰 태그 삭제를 반영한 오프라인 검사에서는 작업은 STOPPED였지만 recoveryVerified=false와 소유권 불일치 오류가 발생했습니다. 실제 AWS에서 재현한 결과는 아니며, 문서화된 제공자 동작을 반영한 로컬 계약 검사입니다.

종료 전에 검증·보존한 소유 증거와 불변 태스크 식별자를 사용해 종료 후 상태를 검증하도록 보완해야 합니다. 태그가 없다는 이유만으로 다른 작업의 종료를 허용하는 방향으로 완화해서는 안 됩니다. 이것과 모델의 수동 롤백·자연 만료 대기 제안을 먼저 고쳐야 짧은 주력 데모가 됩니다.

푸시·배포 상태

로컬 main은 e1d71b6까지 fast-forward했습니다. 저장소의 푸시 전 검증 훅이 기존 승인 기준선과 현재 입력 digest의 불일치로 permissionDecision=deny를 반환했습니다. 실제 원격 푸시와 AWS 배포는 수행하지 않았습니다. 이 검토에서 기준선이나 검증 훅을 우회·변경하지 않았습니다.
