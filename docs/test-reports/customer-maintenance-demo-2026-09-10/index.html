고객 시연 준비 미완료 — 실환경 재시연 중단·정리 완료, 오프라인 보완 검증 완료. 기록된 완주: 0회.

정비 작업이 트랜잭션을 끝내지 않아 쓰기를 막는 잠금을 계속 보유하는 사례다. RCA(근본원인분석)는 연결 부족·느린 쿼리와 이 원인을 구분하고, 사용자 승인 후 해당 작업만 종료해 새 데이터 저장이 회복되는지 확인한다.

고객이 확인할 장면

  1. 저장 실패와 정상 조회가 동시에 나타나는 업무 영향.
  2. 여유 있는 연결 수와 실제 잠금 소유자를 통해 경쟁 원인을 구분하는 과정.
  3. 이번 회차의 작업과 소유 관계를 확인한 복구 절차, 그리고 사용자 승인.
  4. 실제 작업 종료·트랜잭션 롤백 이후 두 개의 완전한 분 구간에서 새 저장 성공, 실패 0, 정상 조회.
  5. 실행 증거와 함께 저장된 회고. 변경이 없으면 그 판단과 근거를 보존.

확인된 수정

  • 도구 준비를 기다리지 않아 목록에서 빠지던 경쟁 상태와 설치 경로 전달 누락을 수정했다.
  • AWS 리전 표시명을 알람 ARN의 API 리전으로 정규화했다.
  • RCA 조회 도구를 역할에 맞게 좁혔고, 모델 결과 내용을 로그에 노출하지 않고 실행 상태를 관찰하도록 했다.
  • DB 관측 서비스와 잠금 소유 작업을 구분하고, 소유 작업의 실제 ECS 식별자·태그·종료 계약을 함께 확인하도록 했다.
  • 새 RCA 실행 절차를 이전 사고의 절차와 합치지 않고 현재 생성된 전체 목록으로 저장하도록 수정했다.
  • 확정 원인은 최초 추정 대신 실제 검증 근거로 표시한다.
  • 승인된 조치 직후의 두 관측 구간을 고정하고, 시간 한도 안에서 지표 도착을 기다리도록 했다. 실패한 관측은 나중의 성공 주장으로 덮을 수 없다.
  • 늦게 전송된 지표가 다음 분으로 넘어가던 오류를 수정했다. 기존 실패 건수를 보존하면서 실제 발생한 분에 집계한다.
  • 회고 입력의 반복 정보를 값 손실 없이 공유하고, 변경 없음 판단도 근거 전체를 저장하도록 수정했다.
  • 따옴표 안의 로그 필터 조건을 셸 명령 연결로 오인하던 판정을 수정했다. 실제 명령 연결과 위험 명령은 계속 차단한다.
