# 검증 순서 변경 제안 — 아직 적용하지 않음

소유 ADR: `docs/adr/agent/0002-hypothesis-tree-lifecycle.md`.
이 파일은 검토용 제안이며 현재 ADR이나 코드 계약을 대신하지 않는다.

## 확인한 문제

배포 누수 시나리오는 확정 원인 하나와 서로 다른 대안 세 개의 판정을 요구한다.
두 엔진 모두 첫 검증 루프에서 확정 원인과 대안 두 개를 검사한 뒤,
신뢰도 0.9 이상에 따른 즉시 종료로 나머지 대안을 `CLOSED`로 남길 수 있다.
`CLOSED`는 기각 판정이 아니므로 해당 회차를 기준선으로 승인할 수 없다.

제약을 모델 입력에 설명하는 수정은 이미 적용했다. 다음 제안은 설명을 넘어
검증 순서의 우선 규칙을 정하므로 별도 확인이 필요하다.

## 제안하는 계약

- 초기 3~5개 루트 가설은 각각 구분해 검증할 수 있는 인과 주장을 표현한다.
  함께 작용하는 기여 요인을 금지하지 않지만, 같은 원인을 전제로 하는 보완 계층을
  별도 대안 원인의 대체물로 취급하지 않는다.
- 현재 확보한 증거로 검증할 수 있는 대안 루트들과 최유력 후보가 한 검증 묶음에
  함께 들어가지 못하면, 해당 대안의 검증을 최유력 후보의 검증보다 먼저 배치한다.
- 대안의 판단 근거는 실제 확보한 증거이며, 우선순위나 낮은 초기 신뢰도만으로
  `REJECTED`를 부여하지 않는다.
- 한 검증 묶음이 모두 기각됐어도 미검증 가설이 남아 있으면 재생성하지 않는다.
  이 항목은 기존 계약을 복원하는 버그 수정으로 이미 반영했다.

## 유지하는 계약

- 검증 묶음 폭 3, 전체 검증 루프 최대 3회, 분기 깊이 최대 3.
- 초기 루트 가설 3~5개, 전체 기각 시 재생성 최대 2회, 부모별 자식 최대 3개.
- 검증 신뢰도 0.8 이상 채택, 0.3 이하 기각, 그 사이는 추가 조사.
- 실제 검증된 채택 가설의 신뢰도가 0.9 이상이면 즉시 종료.
- 0.8 이상 0.9 미만의 기존 비확장 유예·종료 규칙 유지.
- Strands 20분·Codex 60분 예산 유지.
- 종료까지 검증하지 못한 가설은 `CLOSED`로 남기며 기각으로 바꾸지 않는다.
- 평가의 필수 증거와 대안 기각 기준은 완화하지 않는다.

## 비용과 한계

명확한 원인의 확정이 보통 한 검증 루프 늦어질 수 있어 시간과 모델 호출이 늘 수 있다.
기존 시간·루프 한도는 늘리지 않으므로 근거가 부족한 대안은 여전히 미확정으로 남을 수 있다.
새 정책이 모든 모델 평가를 반드시 통과시킨다는 보장은 없고, 적용 후 두 엔진의
네 시나리오를 새로 실행해 확인해야 한다.

현재의 동적 우선순위를 유지하는 선택도 가능하지만, 확인된 실패 회차의 기준선을
그대로 승인할 수는 없다.
