# Vital 이벤트와 재시도 — 승인된 제안 기록

사용자가 아래 제안을 승인했으며 현재 계약은 기존 ADR infra/0004의 센서 입력·저장 규칙과 infra/0007의 데모 완료 기준에 반영했다. 이 문서는 승인 당시 제안의 기록이며 구현·배포 완료 증거가 아니다. 이후 계약 변경은 해당 ADR에서 관리한다.

## 입력과 장애

- Vital Sensor 앱은 심박수 중심의 센서 측정을 생성한다. 서비스 전체에서 신규 이벤트를 초당 한 건 생성하며, 배포 중 여러 태스크가 있어도 생성자는 하나다.
- 이벤트에는 고유 ID, 센서 식별자, 측정 종류, 값, 단위, 원래 측정 시각과 스키마 버전이 있다. 같은 ID를 다른 내용으로 재사용하면 충돌로 거부한다.
- 이벤트 v1의 측정 시각 필드는 `timestamp`, v2는 `sampled_at`이다. 정상 버전은 둘 다 받아 물리 테이블의 `timestamp`에 저장한다.
- 결함 버전은 같은 v2 이벤트를 받지만 INSERT의 물리 컬럼명까지 `sampled_at`으로 바꾸어 PostgreSQL의 실제 `42703` 오류를 발생시킨다. 데이터베이스 컬럼을 결함에 맞춰 바꾸지 않는다.

## 미완료 이벤트와 재시도

- 기존 PostgreSQL에 미완료 이벤트를 보존하는 별도 저장 영역을 추가한다. 생성 직후 보존된 이벤트는 태스크 교체·롤백 후에도 같은 ID·측정 시각·값으로 재시도한다.
- 측정 저장과 미완료 이벤트 완료 처리는 함께 확정한다. 저장 성공 응답이 유실되어 재시도하더라도 한 이벤트의 측정 행은 한 번만 저장된다. 완료된 미완료 레코드는 삭제하되 측정 행은 기존 보존 정책을 유지한다.
- 재시도 간격은 지수적으로 늘리고 무작위 지연을 더한다. 동시 실행 수와 최대 간격을 제한하고 실패한 연결을 반납한 뒤 다음 시도를 예약한다. 신규 이벤트 생성과 재시도를 분리한다.
- 미완료 이벤트는 서비스 전체 최대 86,400건으로 제한한다. 하루 분량의 신규 이벤트를 수용하기 위한 제안값이다. 한도에 도달하면 기존 이벤트를 버리지 않고 신규 생성을 멈추며, 생성하지 못한 건수를 별도 계수한다. 미완료 이벤트는 시간 경과만으로 삭제하지 않는다.
- 모든 앱 태스크나 PostgreSQL이 중단된 동안의 측정은 생성·수신했다고 주장하지 않는다. 재기동 후 해당 구간을 소급 생성하거나 몰아서 보내지 않는다.
- 신규 이벤트, 실제 SQL 시도·실패, 재시도, 미완료 건수, 고유 저장 완료를 구분한다. 환자·센서 값과 SQL 매개변수는 로그·진단 증거에 기록하지 않는다.

## 데모 완료

기존 알람 조건, 승인된 롤백, 배포 수렴, 두 완결 구간의 저장 회복과 서버의 실행 판정을 유지한다. 전체 데모는 추가로 장애 중 보존한 이벤트가 롤백 후 모두 저장되고 중복 행이 없음을 확인한다. 이 추가 확인을 수행하지 않았으면 전체 데모 완료로 표시하지 않는다.

## 선택의 영향

이 제안은 새 외부 큐 없이 기존 데이터베이스를 사용하지만, 새 저장 영역과 이벤트 유일성 규칙을 추가한다. 데이터베이스 자체가 중단된 동안에도 센서 입력을 보존해야 한다면 별도의 내구 저장 경로가 필요하므로 다른 결정이 된다. 미완료 한도와 포화 시 생성 중단도 데이터 의미를 바꾸므로 승인 후 ADR에 반영한다.
