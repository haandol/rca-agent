“권한 부족”의 실제 원인과 수정할 후속 절차

이번 오류는 AWS IAM의 접근 거부가 아니다. 실행 워커는 회고 원문과 변경 내역을 저장한 뒤, 실행 출처가 조기 정상화 런북이면 공용 반영을 차단하고 회고 상태를 FAILED로 기록한다. 공용 플레이북이 나중에 완성돼도 다시 연결하는 경로가 없다.

관련 코드: packages/headless-codex/src/headless_codex/services/execution_pipeline.py의 source_part == "recovery" 분기. 관련 결정은 ADR 0018의 ‘실행과 독립된 원인·운영 분석과의 구분’과 ADR 0008의 ‘완료 후 게시’다.

단기 복구의 RESOLVED는 유효하다. 회고 결과가 없어서 실패한 것이 아니라, 회고를 반영할 정식 공용 원문과의 연결·재개 계약이 빠져 있다. 별도로 관측된 공용 플레이북 생성의 모델 입력 초과도 해결해야 한다.

제안하는 계약

  1. 검토와 공용 반영 상태를 구분한다. 해결된 실행의 회고 원문·변경 내역이 정상 저장됐으나 공용 기준이 아직 준비되지 않았으면 ‘회고 완료·공용 반영 대기’로 기록한다. 실행 RESOLVED와 승인 사본은 바꾸지 않는다. 실제 회고 실패는 실패로 유지한다.
  2. 정식 공용 기준이 확정되면 자동 재개한다. 같은 사고라는 사실만으로 연결하지 않는다. 사고·실행·승인 사본의 지문, 서버가 보존한 공용 개정본과의 불변 연결, 실행 절차 동일성을 검증한다. 완료 전·실패·삭제·만료·손상된 원문은 반영 기준이 될 수 없다.
  3. 기존 사용자 반영 절차를 우회하지 않는다. 기존 공용 플레이북에 대한 분석의 변경 제안이 사용자 검토 대기라면 그 반영을 기다린다. 조기 회고라는 이유로 해당 제안을 자동 승인하거나 공용 지식을 덮어쓰지 않는다.
  4. 보존된 회고만 한 번 반영한다. 롤백이나 모델 회고를 다시 실행하지 않는다. 기준 개정본이 여전히 같은지 확인하는 조건부 갱신으로 중복·동시 변경을 차단한다. 기준이 달라졌으면 반영하지 않고 재검토 필요를 기록한다. 원문과 검색 게시가 모두 일치해야 반영 완료로 표시한다.
  5. 실행하지 않은 절차를 검증됨으로 승격하지 않는다. 검증된 연결과 절차 동일성을 만족하는 경우에만 기존 회고 규칙을 적용한다. 회고가 명령·대상·순서를 바꾼 새 런북은 초안으로 남으며 실행에는 새 승인이 필요하다.
  6. 과거 실패를 지우지 않는다. 기존 FAILED·승인·실행 증거는 그대로 두고 새 후속 시도를 연결해 기록한다. 대시보드는 실행 성공, 회고 검토, 공용 반영 대기·완료·실패를 구분한다.

구현 후 확인할 결과

조기 실행이 분석보다 먼저 끝난 경우와 분석이 먼저 끝난 경우를 모두 검증한다. 중복 전달·동시 개정·다른 사고의 원문·다른 승인 지문·미반영 제안은 잘못된 반영으로 이어지지 않아야 한다. 재개 과정의 인프라 실행 횟수는 0회여야 하며, 이전 실패 기록을 보존한 채 후속 반영 결과를 조회할 수 있어야 한다.

사용자가 이 계약의 구현을 승인했다. 기존 소유 ADR 0018과 관련 ADR에 공용 지식 갱신의 조건·상태 전이를 반영했으며, 이 문서는 승인 당시 제안의 기록으로 보존한다. 현재 구현 기준은 ADR 0018이다. 공용 초안 생성의 입력 초과 문제는 권한 문제와 구분해 수정·검증한다.
