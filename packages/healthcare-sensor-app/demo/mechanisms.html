센서 저장 컬럼 하나로 실패와 복구를 비교한다

정상 이미지 v1은 timestamp 컬럼에 저장한다. 같은 소스를 캡처해 만든 v2는 저장 SQL의 컬럼 이름 한 곳만 sampled_at으로 바꾼다. 실제 데이터베이스에는 sampled_at이 없으므로 PostgreSQL이 INSERT를 거부한다. 오류를 만드는 별도 API는 없다.

요청부터 관측까지

sequenceDiagram
participant C as 센서 요청
participant S as 서비스
participant D as PostgreSQL
participant L as 관측 로그
C->>S: 같은 2행 배치
S->>D: 값을 바인딩한 INSERT
alt v1 정상 컬럼
D-->>S: 실행 성공
S->>D: COMMIT
D-->>S: 커밋 성공
S->>L: write_completed(count=2)
S-->>C: 저장 결과
else v2 없는 컬럼
D-->>S: SQLSTATE 42703
S->>D: 트랜잭션 정리·연결 반환
S->>L: db_write_error (값 제외)
S-->>C: 일반 오류 응답
end
S->>D: 별도 읽기 전용 스키마 조회
D-->>S: 실제 스키마·컬럼 목록
S->>L: db_schema_snapshot

SQLSTATE는 DB 오류 종류를 나타내는 코드다. 42703은 존재하지 않는 컬럼을 참조했음을 뜻한다. 바인딩은 환자 값과 SQL 구조를 분리해 드라이버에 전달하는 방식이다. 커밋은 트랜잭션의 저장을 확정하는 단계이므로 완료 이벤트는 그 성공 뒤에만 남긴다.

같은 스키마의 세 구간

구간요청입증할 결과
정상 v12행 × 3회6행 저장과 커밋 완료 이벤트
변경 v2같은 내용실제 42703 3회, 추가 저장 0행
복구 v1같은 내용6행 추가 저장, 기존 데이터 보존

세 구간 모두 기존 바이탈·이상치 조회와 헬스 응답 본문을 확인한다. 정상 헬스는 status=ok 및 db_connected=true다. 오류 이후 빌린 연결이 0개인지 검사하고, 환자·자격 증명 시험값이 로그·오류 응답·트레이스에 없는지 확인한다.

부모 실행기로 전달할 증거

source_manifest는 실제 설치 소스 지문과 검증 여부를 남긴다. write_contract는 INSERT 컬럼 목록과 SQL 형태 지문을, db_schema_snapshot은 실제 관계와 컬럼 목록을 남긴다. write_completed는 커밋된 행 수다. write_accounting은 VitalIngestAttempts가 성공 또는 실패로 완료된 행 수이며 시작한 행 수와 다르다는 생산자 정책을 기록한다.

CloudWatch 원본 이벤트의 시간·ID·로그 그룹·스트림과 실제 태스크 식별을 함께 보존해야 같은 서비스·구간의 증거인지 판단할 수 있다. 로컬 재현은 AWS 알람이나 에이전트의 승인 복구 검증을 대신하지 않는다.
