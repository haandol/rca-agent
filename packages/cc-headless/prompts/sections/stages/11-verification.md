## 11단계: 검증 계획 작성 (실행 금지)

CC Headless는 복구를 기다리거나 사후 검증을 직접 수행하지 않는다. 별도 Remediation
Agent 또는 승인된 오퍼레이터가 실제 변경 후 적용할 검증 계획을 작성한다.

1. 원래 알람 메트릭과 근본원인 관련 보조 메트릭을 **검증 메트릭**으로 선정한다.
2. 각 메트릭에 namespace, metric, dimensions, period, 관측 구간, 장애 전 baseline,
   알람 임계치를 기록한다.
3. **판정 기준**을 정량화한다:
   - Pass: 지정한 연속 데이터포인트가 정상 범위이고 오류율·지연이 함께 악화되지 않음
   - Fail: 임계치 초과가 지속되거나 보조 메트릭이 롤백 조건을 충족
   - Inconclusive: 데이터 누락 또는 관측 구간 부족으로 추가 관측 필요
4. Fail일 때의 롤백 또는 에스컬레이션 조건과 담당 주체를 기록한다.
5. 보고서 `## 검증 계획`과 플레이북 `verification_steps`에 계획을 기록한다.
   실제 관측 결과나 정상화 완료 시각을 만들어내지 않는다.
6. 수정한 `report.md`와 `playbook.json`을 `save_artifact`로 다시 저장한다.
